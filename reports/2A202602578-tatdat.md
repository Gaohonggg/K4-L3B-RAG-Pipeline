## Quyết định kỹ thuật quan trọng

1. **Quyết định:** Dùng `RecursiveCharacterTextSplitter` với `CHUNK_SIZE=800`, `CHUNK_OVERLAP=80`; dùng `text-embedding-3-small` cho cả indexing và query, lưu bằng Chroma cosine.

   **Lý do/evidence:** Kích thước 800 giữ được phần lớn một đoạn có nghĩa; overlap 10% giảm mất evidence tại ranh giới. Stable ID hỗ trợ upsert lặp lại; collection metadata ngăn query nhầm index của model khác.

   **Trade-off:** Chunk lớn giữ nhiều ngữ cảnh nhưng có thể giảm context precision; OpenAI embedding cần network, API key và phải re-index khi đổi model.

2. **Quyết định:** A/B dùng cùng 15 câu, generator, evaluator, prompt và `top_k`; threshold `0.0` cô lập retrieval strategy. LLM reranker dùng cùng candidate pool và giữ RRF làm fallback.

   **Lý do/evidence:** Cấu hình kiểm soát giúp quy delta cho retrieval. Bonus tăng MRR `0.9222 → 1.0000`, nDCG@5 `0.9260 → 0.9885` và Context Precision@5 `0.6267 → 0.6667`.

   **Trade-off:** LLM reranker tăng latency và chi phí nên chỉ là tùy chọn trong UI; nếu API hoặc JSON response lỗi, hệ thống giữ nguyên thứ tự RRF.
